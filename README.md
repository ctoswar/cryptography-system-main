The **"AC3 level 5 Encryption Algorithm with Caesar Cipher and XOR Cipher"**
thesis (STI College Bacoor, December 2023), rebuilt twice: first hardened
(v2), now made **hybrid** (v3). All five thesis layers survive — framing,
byte Caesar, XOR stream, transposition, XOR + HMAC — but the XOR keystream
is now generated by **AES-256-CTR** (NIST SP 800-38A) and integrity is
**HMAC-SHA256** (FIPS 198-1) in the provably-secure encrypt-then-MAC order.

**One cipher, one envelope, standardized in [`SPEC.md`](SPEC.md) with
byte-exact conformance vectors.**

**Thesis researchers:** Miguel Florencio F. Agapay · Duncan John D. Carpiso · Carlo R. Cobey · Leonavelle Camatog

## Case study: rebuilding a broken thesis cipher — twice

**v1's flaw.** Five stacked XOR passes with static per-process keys. XOR is
associative and commutative, so `k1 ⊕ k2 ⊕ k3 ⊕ k4 ⊕ k5` collapses to a
**single constant XOR** — five "layers" provided exactly one layer of
security, and two known plaintext/ciphertext pairs recovered the combined key.

**v2's fix.** Per-message HKDF-SHA256 subkeys, HMAC-SHA256 integrity verified
before decryption, a master key generated once and never rotated.

**v3's move — the hybrid.** Instead of shipping AES beside the thesis scheme,
v3 put AES *inside* it: the XOR layer keeps its structure, but its keystream
now comes from AES-256-CTR under independently derived subkeys. The classical
layers stay as the thesis identity; the confidentiality and integrity claims
now rest entirely on citable standards. The result is specified formally —
key schedule, envelope formats, MAC transcript — with conformance vectors any
implementation can reproduce byte-for-byte.

**Proof, not promises.**

| Claim | Evidence |
|---|---|
| Correct round-trips | 143 pytest tests: ASCII, Unicode/emoji/CJK/RTL, empty, 150 KB, all 256 byte values |
| Tampering is caught | Per-region tamper tests (nonce/body/tag), wrong-key rejection — all raise `IntegrityError` |
| The key never rotates | Regression test encrypts, simulates a restart, decrypts with a fresh `KeyManager` |
| Files survive byte-for-byte | 100 MB random binary → exact match after decrypt, constant ~29 MB memory |
| The spec is implementable | Byte-exact conformance vectors in `SPEC.md`, asserted by the test suite |
| Structural attacks fail | Truncation, reordering, cross-file splicing, flag/length forgery, trailing data — all rejected by the stream MAC |
| The v1 finding is proven | `evaluation/break_v1.py`: one known pair breaks 8/8 session messages in 0.09 ms; mask == K1⊕…⊕K5 exactly |
| Dependencies are clean | `pip-audit`: 0 known CVEs |
| It's fast | 100 MB file → **161/159 MB/s** encrypt/decrypt (43× v2), p50 latency 0.111 ms, reproducible via `evaluation/run_all.py` |

**Honest limits** (also in `SECURITY.md`): the Caesar/transposition layers
add *no* provable strength — they are keyed structural whitening kept for
thesis continuity. Treat AC3-X as AES-CTR + HMAC with extra transforms. For
adversarial production settings, prefer an audited AEAD (`AESGCM`,
ChaCha20-Poly1305). No forward secrecy; a compromised `.env` reveals all data
encrypted under it.

## The five layers

```
plaintext (UTF-8 bytes)
   │
   ├─ L1  Framing          version byte + uint32 length + payload
   ├─ L2  Byte Caesar      keyed additive shift mod 256 (binary-safe, shift ≠ 0)
   ├─ L3  XOR stream       XOR with AES-256-CTR keystream   ← the hybrid engine
   ├─ L4  Transposition    keyed column shuffle (8 columns, Fisher-Yates)
   └─ L5  XOR + HMAC       AES-CTR XOR pass, then HMAC-SHA256 tag
   │
   ▼
AC3X.<nonce>.<body>.<tag>            (text)
AC3X3\x01 | nonce | chunk_size | frames… | stream_tag   (chunked file stream)
```

- **Nonce:** 16 random bytes per message; every subkey derives from
  `(master key, nonce)` via HKDF-SHA256 — no two messages share key material,
  and per-chunk counter blocks are derived per (layer, chunk index).
- **Integrity:** the tag covers version + nonce + body (text) or the entire
  stream transcript (files); tampering with *anything* → `IntegrityError`,
  never silent garbage.
- **Streaming:** constant memory at any file size; the final stream tag
  verifies before output is committed (atomic staging — a failed decrypt
  never leaves partial plaintext).

## Evaluation & research evidence

The repository is not just a system — it is a reproducible study. One command
regenerates every number, table, and figure:

```bash
pip install -r requirements.txt -r requirements-dev.txt
python evaluation/run_all.py
```

**1. The v1 collapse, demonstrated** (`evaluation/break_v1.py`). v1 was
reconstructed faithfully from the original thesis appendix source code
(`evaluation/v1_reference.py`) and attacked:

- one known plaintext/ciphertext pair + the public `.env` configuration →
  **8/8 session messages broken in 0.09 ms**;
- with *no* configuration at all — only the pairs v1's own `/encrypt` endpoint
  published to Firebase (thesis APPENDIX F) — the Caesar shift, padding
  offset, and full 16-byte mask are recovered by 96-shift brute force +
  periodicity voting in **17 ms**, again **8/8**;
- in both attacks the recovered mask equals `K1⊕K2⊕K3⊕K4⊕K5` exactly: five
  "layers" provided one layer of security. Boot-time key rotation was also
  demonstrated to orphan all earlier ciphertexts.

**2. Performance with real methodology** (`evaluation/benchmarks.py` — 30 reps
per cell, environment recorded in `evaluation/results/`):

| Payload | Encrypt (MB/s) | Decrypt (MB/s) |
|---:|---:|---:|
| 1 KB | 5.5 | 7.6 |
| 64 KB | 242.1 | 218.6 |
| 1 MB | 208.3 | 175.2 |
| 10 MB | 198.5 | 191.0 |
| 100 MB | 161.1 | 158.8 |

Latency (1 KB, n=1,000): p50 **0.111 ms**, p95 0.151 ms, p99 0.200 ms.
Constant memory at 100 MB: peak 29.4 MB encrypt / 25.2 MB decrypt (0.28×
payload). Versus the hardened v2 pipeline (~3.7 MB/s): **43× faster**.

**3. Statistical cipher profile** (`evaluation/cipher_stats.py`):

| Metric | AC3-X | Reference |
|---|---|---|
| Key sensitivity | **50.07% ± 1.06%** | ideal 50% |
| Shannon entropy | **7.9771 ± 0.0017** bits/byte | max 8.0 |
| Chi-square (df=255) | **289.16 < 293.16** | passes uniformity @ α=0.05 |
| Plaintext-bit propagation | 0.087% | AES-CTR baseline 0.049% |

The bit-propagation row is the honest finding worth reading twice: stream
modes (plain AES-CTR included) intentionally propagate no diffusion —
bit-level "avalanche" is a block-cipher property. AC3-X matches its reference
primitive exactly, and the thesis framing is included with the results.
Attack regression tests (`tests/test_v1_attack.py`) keep the evidence alive
in CI: if the demo ever stops reproducing, the suite fails.

**4. The writing scaffold** — `docs/thesis-outline.md` maps every artifact to
a thesis chapter (research questions, methodology drafts, pre-formatted
tables, an honest limitations section) for the continuation write-up.

## Setup

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows:  source .venv/bin/activate elsewhere
pip install -r requirements.txt
```

The first run auto-creates `AC3_MASTER_KEY` in `.env` (already git-ignored). Keep it secret — anyone with the key can decrypt everything.

## Usage

### Web UI + API

```bash
python app.py
# open http://127.0.0.1:8080
```

| Endpoint | Body | Returns |
|---|---|---|
| `POST /encrypt` | `{"message": "..."}` | `{"ciphertext": "AC3X...."}` |
| `POST /decrypt` | `{"ciphertext": "AC3X...."}` | `{"plaintext": "..."}` |
| `POST /encrypt-file` | multipart `file` | downloadable `*.ac3` |
| `POST /decrypt-file` | multipart `file` | decrypted download |
| `GET /health` | — | `{"status": "ok", "version": 3, "algorithm": "ac3x"}` |

Uploads are capped at 64 MB (the CLI streams files of any size). Invalid or tampered input returns `400` with a reason — never a stack trace.

### CLI

```bash
python cli.py encrypt "secret message"
python cli.py decrypt "AC3X...."
echo "from a pipe" | python cli.py encrypt -
python cli.py encrypt-file video.mp4                 # -> video.mp4.ac3 (streams, any size)
python cli.py decrypt-file video.mp4.ac3             # -> video.mp4 (refuses to overwrite differing files)
python cli.py keygen                                 # create the master key if missing
```

### Library

```python
from ac3 import AC3Cipher, CMainController

cipher = AC3Cipher()                             # auto-loads .env key
token = cipher.encrypt("hello ñ")                # AC3X.… text envelope
plain = cipher.decrypt(token)

ctrl = CMainController()
ctrl.encrypt_file("notes.txt")                   # -> notes.txt.ac3 (chunked stream)
ctrl.decrypt_file("notes.txt.ac3")
```

## Honest security assessment

This project is an **educational artifact** and portfolio piece — not a drop-in replacement for vetted cryptography.

- *Genuinely standard:* AES-256-CTR (SP 800-38A), HMAC-SHA256 (FIPS 198-1),
  HKDF-SHA256 (RFC 5869), encrypt-then-MAC composition — each citable, each
  exercised by conformance vectors.
- *What the hybrid is:* the thesis's five layers with a standard engine; a
  clean, specified construction whose security case rests on those primitives.
- *What the hybrid is not:* it does **not** add provable strength over plain
  AES-CTR + HMAC — the Caesar/transposition layers are keyed whitening, and
  the scheme has not been independently audited. It provides no key exchange,
  no forward secrecy, and no protection against `.env` compromise.

**For adversarial production data, call `cryptography`'s `AESGCM`/`Fernet`
directly.** The value of AC3-X is the demonstrated path from a broken thesis
cipher to a specified, tested, honestly-documented hybrid — and a formal spec
others can implement and verify.
